# Documentation

bust writes documentation of the register map to `doc/`, in the output directory of the module described in [Command line](command-line.md#output-directory): as HTML, Markdown and LaTeX, and as PDF when `pdflatex` is installed. None of it needs anything beyond bust itself, except the PDF. This page describes each file and shows it for the prototype example.

| File            | Content                                | Written                                                         |
|-----------------|----------------------------------------|-----------------------------------------------------------------|
| `<module>.html` | The documentation as one HTML page      | Unless you give `-d`                                            |
| `<module>.md`   | The documentation as Markdown           | Unless you give `-d`                                            |
| `<module>.tex`  | LaTeX source of the documentation       | Unless you give `-d`                                            |
| `<module>.pdf`  | The documentation as PDF                | Unless you give `-d` or `-p`, when `pdflatex` is on your `PATH` |

## Content

`doc/<module>.tex` and `doc/<module>.html` have the same content and layout, and the PDF is built from the `.tex` file. They contain:

- A title with the module name, the `version` of the module, the hash of the
  register map, and the date and
  time of the run (for the PDF, the time it was built). Each page has `Generated by bust` and the bust
  version at the top.
- The `description` of the module.
- **Register List**, a table of every register with its number, name, software
  and hardware access, address, type, width and reset value.
- **Registers**, a section for each register with its description and a
  diagram of its bits, with the field names, bit positions and reset values.
  The bits that no field covers are marked unused, or reserved with [`reserved_fields`](register-map-format.md#reserved-fields). A register with fields
  also gets a list of them, with the description, `sw` and `hw` of each field,
  and its `onread`, `onwrite`, `singlepulse` and enumeration values where it
  has them.

In descriptions, a `` `code` `` span is set in typewriter type. In the LaTeX document, a character that LaTeX cannot print, such as an emoji, is left out.

This is the section for `reg11` from `prototype.tex`:

```latex
\begin{register}{H}{reg11 - RW/R}{0x0000002C}  \par Enumerated field. \regnewline
  \label{reg11}
  \regfield{unused}{30}{2}{-}
  \regfield{field0}{2}{0}{{0x0}}
\reglabel{Reset}\regnewline
  \begin{regdesc}\begin{reglist}[field0]
    \item [field0]  (sw: rw, hw: r; values: STATE0=0, STATE1=1, STATE2=2, STATE3=3)
  \end{reglist}\end{regdesc}
\end{register}
```

## HTML

`doc/<module>.html` is one self-contained file: the styles are in the page and the bit diagrams are inline SVG, so it opens in any browser and can be copied or served on its own. On top of the layout of the LaTeX document it adds links: each row of the register list links to the section of its register, a sidebar lists every register, and each section links back to the register list. The page has a print stylesheet that hides the sidebar and the links back, so printing it to PDF from a browser gives a clean document without `pdflatex`.

## PDF

When `pdflatex` is on your `PATH`, bust runs it once on the `.tex` file to make the PDF:

```bash
pdflatex --interaction=batchmode --output-directory=<doc dir> <doc dir>/<module>.tex
```

`pdflatex` must be on your `PATH`, with the LaTeX packages the document uses:
`fancyhdr`, `datetime`, `geometry`, `register`, `enumitem`, `calc`, `tabularx`
and `listings`. On Debian and Ubuntu, the packages `texlive-latex-base`,
`texlive-latex-recommended` and `texlive-latex-extra` provide them.
`pdflatex` writes `<module>.pdf` to `doc/`, together with its `<module>.aux`
and `<module>.log` files.

When `pdflatex` is not on your `PATH`, bust writes the `.tex` and `.html` files, prints `pdflatex is not on PATH, so bust skipped the PDF.` followed by the path of the HTML page, and exits with status 0.

bust runs `pdflatex` in batch mode and does not show its output. When
`pdflatex` reports errors, bust prints `pdflatex reported errors. See
<doc dir>/<module>.log`. When it cannot run `pdflatex` at all, it prints
`Could not run pdflatex (...). Use -p to skip the PDF.` In both cases it
carries on: the other files are written and bust exits with status 0.

To build the PDF in your own flow instead, give `-p`. bust then writes the
`.tex` and `.html` files but does not run `pdflatex`. Give `-d` to skip the documentation
altogether.

## Markdown

`doc/<module>.md` holds the register map as Markdown, for reading on GitHub or GitLab or in an editor, with no LaTeX needed. It has a line with the bust version, the `version` of the module and the hash of the register map under the title, then the `description` of the module, a **Register list** table where each name links to its register, and a **Registers** section with a table of the bits of each register. The bits table lists the fields from the highest bit down, with their bits, name, `sw`, `hw`, reset value and description, followed by the `onread`, `onwrite`, `singlepulse`, hardware modifiers and enumeration values where the field has them. Bits that no field uses are listed as unused, or as reserved with [`reserved_fields`](register-map-format.md#reserved-fields). A register without fields gets one row, named after the register.

In descriptions, a `` `code` `` span is kept, and the characters that Markdown would read as markup, such as `*` and `|`, are escaped. Line breaks become spaces.
